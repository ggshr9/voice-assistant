# 实时字幕翻译 设计文档

日期：2026-06-20
状态：已确认需求，待写实现计划

## 一句话
开会时把**对方说的外语**实时转写并翻成中文，以**屏幕底部双语字幕条**显示。本地、通用于任何会议软件(腾讯/Zoom/Google Meet)、不抢麦。

## 目标 / 非目标

**目标**
- 转写并翻译**远端(对方)**的外语语音 → 中文。
- 屏幕底部置顶半透明字幕条，**双语对照**(原文一行 + 中文一行)。
- 全本地：whisper(STT) + Qwen3.6(翻译)。
- **不碰麦克风**，会议软件的麦全程可用。
- 「均衡」实时性：按说话停顿(VAD)切句，一句说完约 1-3 秒出译文。

**非目标(YAGNI)**
- 不转写/不翻译**自己**说的中文(本次只为「听懂对方」)。
- 不做会后纪要(那是 `meeting`/`minutes` 的事；字幕与录音是两个独立模式)。
- 不把字幕回灌进会议给对方看(只在本机显示)。
- 不做双向、不做多目标语言(本期固定 外语→中文)。

## 已确认的需求决策
1. 方向：**外语 → 中文**。
2. 与录音关系：**字幕是单独模式**，只读 BlackHole(远端声音)，不录麦、不出纪要。
3. 显示内容：**双语对照**(原文 + 中文)。
4. 位置：**屏幕底部字幕条**(置顶、半透明、点击穿透)。
5. 实时性：**均衡**(VAD 按句切，句末约 1-2 秒出译文)。

## 架构 / 数据流

```
系统输出 → 会议外放(扬声器 + BlackHole)      ← 启动时自动切；不碰麦，Meet 麦正常；停止切回原输出
              │
              ▼
        BlackHole 2ch  ──采集(sounddevice)──▶  环形音频缓冲
              │
              ▼  webrtcvad 检测语音/静音
        VAD 切句：累积语音帧，静音 ~0.7s 视为句末；或累计达上限(~10s)强制切
              │ 一句外语音频(wav bytes)
              ▼
        STT：POST stt_server(8082, whisper-large-v3-turbo)，自动检测语种 → 外语原文
              │ {text, lang}
              ▼
        翻译：POST Qwen3.6(8080)，system=「译成简洁中文」，enable_thinking:false → 中文
              │
              ▼
        字幕浮窗(pyobjc NSPanel)：显示「原文 / 中文」，保留最近 1-2 句，旧的淡出
```

## 组件(各自独立、可单测)

### 1. `caption.py` — 编排器(主进程)
- 职责：音频采集 + VAD 切句循环；每句依次 STT→翻译→推给浮窗。生命周期管理(启动切输出、停止切回)。
- 依赖：sounddevice、webrtcvad、stt_server(8082)、Qwen3.6(8080)、caption_overlay。
- 接口：
  - `start()`：记录当前输出→切到 `会议外放`；起采集线程 + 处理线程；显示浮窗。
  - `stop()`：停线程、关浮窗、切回原输出。
  - 内部 `on_segment(wav_bytes)`：STT→翻译→`overlay.update(orig, zh)`。
- 线程模型：采集线程(实时喂 VAD)→ 切好的句子放队列 → 工作线程消费(STT+翻译，可能耗时)。**浮窗更新必须回主线程**(pyobjc 主线程)，用 `performSelectorOnMainThread` 或主线程轮询队列(同菜单栏 app 踩过的坑)。

### 2. STT — 复用 `stt_server.py`(8082, mlx-whisper)
- 输入：wav bytes 或临时 wav 路径。输出：`{text, language}`。
- **需小改**：确认它**自动检测语种并返回原文**，而不是写死中文(`language=None` 让 whisper 自检；返回 detected lang)。
- whisper-large-v3-turbo 多语种、英语强，适合转外语。

### 3. 翻译 — Qwen3.6 @ 8080
- 输入：外语原文 + 源语种。输出：中文。
- 请求：`/v1/chat/completions`，system=「你是同声传译。把下面这句{lang}译成简洁、口语化的中文，只输出译文，不要解释」，`chat_template_kwargs:{enable_thinking:false}`，`repetition_penalty:1.1`，`max_tokens` 适中，`temperature` 低。
- 源语种已是中文则跳过翻译(直接显示)。

### 4. `caption_overlay`(pyobjc NSPanel)— 字幕浮窗
- 无边框、`NSWindowStyleMaskBorderless`；`level = screenSaver/floating`(置顶)；`ignoresMouseEvents=True`(点击穿透)；`nonactivating`(不抢焦点)；半透明黑底白字。
- 贴屏幕底部居中，宽度约屏宽 80%。
- 接口：`update(orig:str, zh:str)`、`show()`、`hide()`、`set_interim(text)`(可选：处理中显示「…」)。
- 只保留最新 1(-2)句；可后续加淡出。

## 启动方式
- 菜单栏 `会议纪要.app` 加一项 **「🌐 实时字幕」开/关**(点开启动 caption 进程、点关停止)。
- 同时提供 CLI `caption`(`~/.local/bin/caption`)：前台跑，Ctrl+C 停。
- 字幕作为**独立进程**(有自己的 GUI 运行循环)，与录音/纪要互不干扰。

## 错误处理
- `会议外放` / BlackHole 不存在 → 弹窗/报错提示先建聚合设备，不静默。
- 8082 / 8080 未就绪 → 启动时检测，提示先 `llm start` / 起 stt_server(或自动拉起，同 chat.py)。
- 某句 STT 或翻译失败 → 跳过该句，不中断整条流水线(同语音助手「单句失败不中断」)。
- whisper 幻觉(静音/噪音转出重复字)→ 复用 `is_hallucination()` 过滤，不显示。
- 停止/退出/异常 → **务必切回原输出**(try/finally)，否则系统输出卡在会议外放。

## 测试策略
- **VAD 切句**：喂一段含停顿的 wav，断言切出的句数/边界合理。
- **翻译**：给定外语句 → 调 8080 → 断言返回非空中文、无 `<think>` 泄漏。
- **STT 复用**：POST 一段英语 wav → 断言返回英文原文 + `language=en`。
- **整链(离线)**：用一段已知英语会议录音喂 caption 的处理函数(stub 浮窗)→ 断言产出「原文/中文」序列。
- **浮窗**：手动验证(置顶、穿透、不抢焦点、底部居中)——GUI 没法自动点。
- **输出切换 try/finally**：模拟处理中抛异常 → 断言输出仍被切回。

## 风险 / 已知限制
- **延迟**：句末到译文现实约 1-3 秒；快节奏抢话跟得吃力。
- **whisper 对吵杂会议音/专有名词/口音**偶尔听岔 → 双语对照兜底(能看原文)。
- **机器负载**：whisper + 35B 翻译持续跑，M5 Max/128G 可扛；嫌慢可换更小翻译模型(本期先用 Qwen3.6)。
- **pyobjc 点击穿透/不抢焦点浮窗**是最需要调的一块。
- **菜单栏 app 集成**：caption 浮窗有自己的 GUI 循环，不能塞进 launchd 的菜单栏进程里跑；菜单项以「启动/停止独立 caption 进程」方式集成(同录音 shell-out 思路)。
- Google Meet 自带翻译字幕可能已够用；本方案价值在「通用 + 本地」。

## 开放的实现细节(写计划时定)
- VAD 静音阈值、句子最大时长(初值 0.7s / 10s)。
- 浮窗精确样式(字号、透明度、底边距)。
- caption 进程的启动/存活方式(是否同菜单栏 app 一样走 launchd 规避「负责进程回收」——caption 由菜单栏 app 启动时会遇到同样问题，需复用 launchd 方案)。
- stt_server 是否需要新增「返回 detected language」字段。
