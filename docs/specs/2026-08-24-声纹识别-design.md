# 声纹识别：自动认出会议里的每个人

> 状态：已批准，进入实现　|　2026-08-24

## 问题

`minutes` 靠手动传 `--me 说话人N` 才能把待办分成「我的/他人」。这要求每次会后先打开
`_annotated.txt` 肉眼找哪个是自己。而所有说话人在纪要里都是 `说话人A/B/C` 这样的匿名牌，
读纪要的人得自己对照。

## 可行性（已实测，不是推测）

pyannote community-1 的 `DiarizeOutput.speaker_embeddings` 给出 `(N, 256)` 向量，
与标签顺序对齐、无 NaN。

| 比较 | 余弦 |
|---|---|
| 同一个人的两段独立录音 | **0.876** |
| 陌生人（那场会 8 人 vs 我的声纹） | −0.049 ~ **0.068** |
| 同一个人跨独立分人（半场会 A → B） | **0.882 / 0.943** |
| 跨段匹配时与次高者的差距 | **+0.686 / +0.754** |

同人与陌生人差一个数量级，门槛好设。

**副产品**：我不在 `线上会议_20260619_2301` 里（8 人全部 ≈0），此前拿它试 `--me` 本就无意义。

## 关键约束

1. **必须复用分人当次的向量，不能事后另跑一遍 pyannote。** 第二次跑的聚类不保证与第一次
   一致，标签对不上就全错。这是正确性问题，不是性能问题。
2. **上游把向量丢了。** `mlx_qwen3_asr/diarization.py` 从 `DiarizeOutput` 只取标注。
   但我们已经在 `bin/_asr_mps.py` 里挂着 `_load_pyannote_pipeline`，再包一层即可截获。
3. **声纹是生物特征，不进 git。** 代码要可追溯、这类数据要可删除，生命周期相反，
   混在一起以后一定后悔。数据放 `~/.config/`，由 `sync-web` 显式推送到服务器。

## 数据结构

`~/.config/voiceprints.json`

```json
{"version": 1, "people": [
  {"name": "张三", "is_me": true,
   "embeddings": [[...256...], [...256...]],
   "sources": ["降噪_我的声音.wav", "转写_线上会议_20260619_2301/说话人C"],
   "updated": "2026-08-24"}
]}
```

一个人存**多条**向量而非平均，匹配取最大相似度：既是多人场景的口子，也让同一个人在不同状态
（远近麦、中英文、感冒）下越用越准。`is_me` 取代 `--me`。

## 注册的两种方式

- **命名式（主路径）**：`who label <转写目录> 说话人C 李四`
  从旁路向量文件取该说话人的向量入库。**没人需要念稿子**，素材是真实会议里的自然对话。
- **朗读式（保留）**：`who enroll <音频> 张三 --me`。网页版后续可做成「说几句话」按钮。

## 匹配规则

分人完成后，每个 `SPEAKER_xx` 的向量与注册表比对：

- 相似度 **≥ 0.55** 才认（实测同人 0.88+、陌生人 ≤0.19）
- 且**高出次高者 ≥ 0.15**，防止两个注册者都沾边时瞎选
- **一对一**：一场会里一个人只占一个说话人位，反之亦然（按相似度降序贪心分配）
- **认不出保留 `说话人X`**，永不瞎猜

匹配结果传给 `_annotate.py` 做标签替换；`minutes` 由 `is_me` 自动定「我」；
`--me` 保留为手动覆盖。

## 纠正

`who label` 对同一场会重打 → 新向量**追加**进该人（纠正 + 学习）。
`who forget <名字>` 整条删除。

## 改动清单

新增：`bin/_voiceprint.py`（核心纯函数）、`bin/who`（CLI）
修改：`bin/_asr_mps.py`（截获向量写 `.embeddings.npz`）、`bin/meeting`（接匹配）、

　　　`bin/sync-web`（推声纹表）、`.gitignore`
服务器：`web/meeting/asr_diarize_step.py`（就地取向量 + 匹配）
